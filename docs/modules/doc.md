# DOC oscillator engine (`mod_doc8_5` / class `Cdoc`) → `sq8l::Doc`

Original code range 0x45b9b4–0x45cf38 (plus the pitch lookup `FUN_0045b8b4` of the small
unit before it, "docPitch", and the wavesample lookup `FUN_00455f0c` of unit_455f34).
C++: `src/engine/Doc.{h,cpp}`, tables in `src/engine/data/DocData.cpp`
(generated by `re/scripts/extract_doc_data.py`), test API `tests/capi_doc.cpp`,
differential test `tests/test_doc.py`.

## What it does

One `Cdoc` object (10400 bytes) serves all 16 voice slots. Per voice:

1. **Three DOC 5503 oscillators** step at the DOC's own rate, `docRate = 38455.855 Hz`
   (float 0x471637db), independent of the host rate. Each has a 24-bit-ish phase accumulator
   (`acc`, mask `2^(res+17)-1`), a 16-bit frequency register (`freq`), and reads 8-bit
   samples from the 256 KiB wave ROM at `((acc >> (res+17-size)) + bank<<16 + page<<8) & 0x3ffff`.
   As on the real chip a zero byte halts the oscillator. Waves ≥ 54 are one-shot: the
   oscillator halts after one pass (mode 1) and its phase restarts on every recalculation
   (exceptions: osc 1 loops when AM is on, and is the sync slave, mode 2, when SYNC is on).
2. **Mix**: `sum = Σ (s_i − 128)/127 · amp_i` (osc 0 is left out when its `enabled` is 0, which
   happens when it runs only as a sync/AM source). `amp_i` follows a one-pole smoother towards
   the DCA level (pole `0.01^(1/(0.002·docRate+1))`: −40 dB in about 2 ms).
   * **Sync** (`sync != 0`): when osc 0 wraps, osc 1's accumulator is cleared (osc 1 mode 2).
   * **AM** (`amMode == 1`): osc 0 is silent and drives osc 1's amplitude:
     `amp1 = pole' · amp1 + (s0 · 0.6/127 + 0.4) · (1 − pole')` with a 0.2 ms pole (`s0` =
     raw sample − 128; the result can go negative); the levels of
     osc 0/1 are forced to 0x7f00 and both are forced on.
   * **AM bug** (`amBug != 0`, all factory programs): in AM mode osc 1 takes bit 0 of its wave
     ROM bank from osc 0's wavetable register (SQ-80 firmware bug; audible with one-shot waves).
3. The mixed DOC sample (+ an alternating ±1e-10 anti-denormal offset) enters a 4-sample
   history. A **polynomial resampler** (30-bit phase, increment `docRate/sr · 2^30`) produces
   one output per host sample. (port) The increment is per voice (`clock[v].phaseInc`), which
   is how MTS-ESP retunes a voice without touching its frequency register — see
   [tuning.md](tuning.md); it holds the nominal value for every voice unless a master is
   active. The order (0–4) is chosen in `update()` from the fastest table
   step rate of the enabled oscillators (`freq << (size−1−res)` vs 576717 / 1631846 / 6918636):
   1 = linear, 2 = quadratic, 3/4 = cubic/quartic whose first coefficient continues the
   previous segment's slope (dropped when |slope| < 0.001).
4. Optional **DC blocker**: RBJ high-pass at 15 Hz, α = sin ω / 1.41422 (Q ≈ 0.707) (DC-BLOCK = SMART/ON/OFF is
   resolved by plugCore into `dcBlock`; SMART = on when SYNC is on).

The output sample is returned (in the original: left in ST0) and goes straight into the
filter (`FilterSQ::process`).

they are mode-sensitive only through `setAmpTarget` (reset) – stopVoice has no FPU code.

### `update(v)` in detail

1. AM mode forces `osc[0..1].enabled = -1`, `level = 0x7f00` in the parameter block.
2. `newNote`: `dcBlock > 0` → clear DC history and enable, else disable.
3. Keys: if `forceRecalc` or a key differs, take both keys and recompute every oscillator.
4. `smoothMode = init ? 0 : levelSmoothing`.
5. Per oscillator: disabled (and not the sync/AM source of an enabled osc 1) → cleared and
   halted. Otherwise, when the key, wave, semitone, fine or (osc 1) the sync mode changed:
   wavesample lookup at key `waveKey + semitone` (`FUN_00455f0c`: page, wavetable register,
   semitone offset, fine offset), octave normalisation of `semitone + offset` into 12..35 by
   moving the DOC resolution (`FUN_0045c470`), `pitch = (pitchKey + s)·256 + fine·8 + fineOfs`.
   Then always: `freq = docPitchToFreq(max(pitch + pitchMod, 0) − 16)`; phase reset
   (`resetPhase` or a one-shot wave) or, on `init` with a linked voice, copy `acc/wrapped` from
   the linked voice's same oscillator (soft voice stealing keeps the phase); `halted = 0`;
   amplitude target from `levelToAmp(level)` (`init`: immediate; EMU: previous level, one control
   tick late; FAST: new level).
6. Interpolation order from the enabled oscillators' step rates.

## How plugCore drives it

* construction: `Doc(16)`; `setNumVoices`, `resetAll`, `setSampleRate` at start-up;
* note on (FUN_004625d4): `startVoice(v, key, linkedVoice, newNote, resetPhase)` and, when
  gliding, `setPitchKey(v, startKey)`;
* control rate (FUN_00463890, every 1024/`master+0xf80` samples per voice), alternating:
  tick A: write `params(v)` (`osc[i] = {enabled, wave, level, octave·12+semi, fine, pitch
  modulation}`, `amMode`, `sync`, `amBug`, `flag70`, `levelSmoothing` (option override
  `master+0xfec` or program), `dcBlock` (override `master+0xff4` or program)) then `update(v)`;
  tick B: `interpolateLevels(v)`;
* every sample (FUN_00464410): `x = render(v)` → filter → amp; while the amp is inactive
  `stopVoice(v)` each control tick, and the voice is dropped once the amp's countdown passes
  `-releaseSamples`;
* voice off (FUN_00462e30): `stopVoice(v)`.

plugCore accesses directly: the parameter blocks (through `params(v)`) and `releaseSamples`.
The LFOs keep a pointer to the Doc for the wave ROM (`lfoWaveLocation` in C++ needs none).
No other shared global state; the two static tables are read-only.

## Quirks reproduced

* `render()` advances the DOC only when the resampler phase wrapped *during the previous call*
  (`phase <= prevPhase` is tested before the increment). For sr < docRate several wraps would be
  merged; plugCore rejects such rates anyway.
* An accumulator equal to the mask after the add counts as a wrap (`>=`).
* Wraps are flagged on the step whose add overflows and handled on the next step that reads a
  sample: a one-shot oscillator therefore plays one more sample (from the wrapped position)
  before halting; for sync, osc 1's accumulator is cleared in that next step before osc 1
  reads, so both restart together.
* The octave normalisation increments/decrements the whole wavetable-register byte, so an
  overflowing resolution carries into the table-size bits (all byte arithmetic kept).
* `docPitchToFreq` folds pitches ≥ 0x8000 down by octaves; it interpolates the 2049-entry
  table at odd 1/32-semitone steps (entry 0x800 duplicates 0x7ff).
* The slope-continuity test of the order 3/4 resampler compares the unrounded (double) slope,
  then uses the value stored as Single.
* In path A the silent osc 0 contributes `0.0 + …` (sign of zero kept exactly as on the x87).
* The original returns from `render` with `FFREE ST1/ST2` instead of popping (the x87 TOP
  rotates by two per call; harmless).
* `setSampleRate` would overflow `Trunc` (→ 0x80000000) for sr < docRate/2; reproduced.
* **Uninitialised stack byte (not reproducible bit-exactly):** in `update`, osc 0's wavetable
  register used by the AM bug comes from a stack local that is only written when osc 0 is
  recalculated in the same call. If, in AM mode with the AM bug on, osc 1 is recalculated
  while osc 0 is not (only possible by editing osc 2's wave/semitone/fine or toggling sync
  while a note sounds), the original reads whatever an earlier call left in that stack slot.
  The port uses osc 0's current bank bit 0 (= what that byte held after osc 0's last
  recalculation, the intended value). The test pokes that stack byte before fuzzed calls and
  confirms by flipping it that the original reads it there; factory-program playback never
  takes this path.

## Verification

static tables vs emulator memory, helper routines over their whole input ranges, every entry
point traced and replayed during playback of 41 bank C/D programs (AM, sync, one-shot, drum,
noise, glide, restart; keys 0..127) at 44.1 kHz, the same with emulation-option overrides
(FAST / no level interpolation, DC block on/off), a few programs at 48 and 96 kHz, plus state
fuzzing of every entry point on a scratch copy of the object. All comparisons are exact (FPU
