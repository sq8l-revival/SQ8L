# Envelopes: unit `mod_env_2`, class `Csq_env` -> `sq8l::Env`

Code range 0x45dba0-0x45e32c. C++: `src/engine/Env.{h,cpp}`, tables in
`src/engine/data/EnvData.cpp` (generated by `re/scripts/extract_env_data.py`).
Test: `tests/test_env.py` (C API in `tests/capi_env.cpp`). Bit-exact (see "Verification").

SQ-80 4-stage envelope (L1-L3, T1-T4, LV, T1V, TK) plus the SQ8L extras of readme D.3:
start level L0, per-envelope CYC, smoothing SMTH, MODE-T1V (T1 / SMT), output SHAPE, and the
SQ-80 "R" second release (T4 bit 6). All envelope arithmetic is 32-bit integer (8.8 fixed point);
only the control-rate setup uses the FPU.

The two Delphi method pointers are modelled as enums (`Env::Ramp`, `Env::Next`); the code
addresses are listed in `Env.h` and mapped by `tests/capi_env.cpp`. `None` is the nil pointer of
a zero-filled object before the constructor's reset (the original tests `Assigned()` first).

### Patch envelope record (14 bytes at patch + 0x6a + 14*i), see `EnvRecord`

0 L0, 1 L1, 2 L2, 3 L3, 4 L4 (unused), 5 LV (0..63 "L" linear, 64..127 "X" exponential),
6 T1V, 7 T1, 8 T2, 9 T3, 10 T4 (+0x40 = "R"), 11 TK, 12 flags (bit 0 CYC - read by plugCore,
bits 1..3 SHAPE 0=OFF 1..7=EXP,EXP2,EXP3,EXP4,TAN,TAN2,TAN3, bit 4 MODE-T1V=SMT), 13 SMTH.

## Semantics

**start** (note on): velocity clamped to 0..127 (FUN_00450d90).
* `levelScale = (LV * curve[vel] >> 5) + (63 - LV) * 4` with `curve = LV < 64 ? kVelocityCurveLinear
  : kVelocityCurveExp`. LV=0 gives 252. Quirk: for "X" values (64..127) the raw byte (incl. the
  +64) is used, so `(63 - LV) * 4` is negative: at low velocities the scale is <= 0 and the
  envelope levels are inverted (e.g. LV=127, vel 0: -256). Reproduced exactly.
* `timeKeyScale = TK * max(0, 2 * (key - 36)) / 256` (toward zero). Applied to T2 and T3 only,
  not to T1 nor T4.
* MODE-T1V = T1: T1 is shortened by `(T1V * vel) >> 7` (unsigned shift); smoothing = SMTH*4.
  MODE-T1V = SMT: smoothing amount = `SMTH*4 - ((T1V * vel) >> 5)`.
* smoothing amount n (<= 0: off; else min(n, 255)): `a = 255 - ((255-n)^2 >> 8)`.
* `restart != 0` (no previous voice, or REST.ENV on): value = smoothed = L0<<8, output = L0.
  Else with `prev` (env i of the previous voice of this note, may be this object): continue from
  prev's value/smoothed/output. smoothed and output are zeroed *before* copying, so with
  prev == this only `value` survives (smoothing restarts from 0). With restart == 0 and no prev
  (never done by plugCore) value is kept, smoothed/output zeroed.
* first segment: target `L1 * levelScale / 256`, time `T1 - t1Offset`.

**Segments** (`startSegment(target, time)`): time clamped to 0..63, `ticks = max(1,
Round(Single(kEnvTimeTable[time] * rateScale)))` (current rounding mode), linear ramp with
`step = (|target - value/256| << 8) / ticks` (truncated). The ramp clamps at the target and, when
the ticks run out, sets `value = target*256 + (value & 0xff)` (the fraction of the running value is
kept - quirk) and calls `next`. Equal levels use the Hold ramp (just counts ticks).

Stages: L0 -> L1 (T1) -> L2 (T2-TK) -> L3 (T3-TK) -> `Sustain`: if `value == 0` finish; else if
released or CYC: release; else sustain (`sustaining = 1`, ramp idle).

**release** (note off): ignored when CYC. With the hold pedal down (master+0x11420) only
`releasePending` is set; the next `tick(pedal up)` performs it. Release = T4 ramp to 0 then
`finish`; with "R": ramp to `value/512 - 12` (half the level minus 12) in T4, then to 0 in time 39.
`finish` sets `finished`; the next tick clears `active` (with smoothing: once `smoothed/256 == 0`).

**tick** (control rate, ~83.59 Hz): returns 0 if not active; pending release; ramp; then
`smoothed = (smoothed*a + value*(256-a)) / 256` if smoothing; `output = smoothed/256` (or
`value/256`); returns `shaped()`.

**shaped**: OFF -> output. Else `idx = (output*256 / levelScale + 128) & 255`,
`return table[idx] * levelScale / 256`. All divisions by 256/512 round toward zero.

## How plugCore drives it

* Construction: 4 envelopes per voice slot at slot+0x64..+0x70 (slot = master + 4 + 0xe8*i),
  `init(83.592575f)`; then FUN_00462380 calls `setRate(83.592575f)` on all of them (rate changed
  from 0). `setRate` resets the envelope, so it must not be called while voices play (the
  original only calls it when the control rate value changes).
* Note on FUN_004625d4 (only if its "start envelopes" argument is set), for env i:
  `rec = patch + 0x6a + 14*i`, `cycle = patch[0x177] (global CYC) > 0 || rec[12] & 1`;
  if the note restarts a previous voice (REST.VC, same key; slot+0x28 = previous slot):
  `start(rec, key, vel, restart = patch[0x175] (REST.ENV) > 0, cycle, prevSlot.env[i])`,
  else `start(rec, key, vel, 1, cycle, nullptr)`. key = clamped key, vel = raw velocity byte.
* Note off FUN_00462de4 (voice active, not yet released): `env[i].release(pedal)` for i=0..3.
* Control tick FUN_00463890: `out[i] = env[i].tick(pedal)` stored at slot+0xa8+4i;
  later `env[3].shaped()` again for the final amplitude.
* Per sample FUN_00464410: the control tick runs only while `env[3].active`; when env 4 is
  inactive the voice is stopped (FUN_0045bd78).
* `pedal` = `master+0x11420 != 0` (CC 64 hold).

All plugCore calls happen inside processReplacing (round toward zero) except construction /
setRate (round to nearest). With rateScale = 1.0 the rounding mode does not change anything in
this unit, but the C++ honours the current mode anyway.

## Quirks / unreachable paths

* **Divide fault**: `shaped()` divides by `levelScale`. With SHAPE != OFF and an "X" LV, 36
  (LV, velocity) pairs give `levelScale == 0` (LV=64 at velocities 16..23, LV=65 at 32..35,
  66 at 40..43, 67 at 48..51, and single velocities for LV 70, 72, 76, 78, 79, 82, 83, 84, 96,
  98, 103, 106, 112, 115, 122, 126) and the original raises an integer divide exception inside
  processReplacing (verified in the emulator). The C++ returns 0 (the limit: the table value is
  multiplied by 0). `INT_MIN / -1` (also a fault) cannot happen with real levels; C++ wraps.
  For "X" LV values 5652 of the 64*128 (LV, velocity) pairs give a negative scale (inverted
  envelope).
* The nil checks of the method pointers are always true after construction.
* `sustaining` (+0x61) and `level[4]` (+0x14) are written but never read (not by mod_env_2,
  not by plugCore).
* `reset()` does not clear `shapeTable`, `smoothA/B`, `cycle`; harmless since `active` is 0.
* Unused shape table 7 (TAN4) is only reachable by the LFO (waveforms 75..82 use the same
  8 tables at 0x4c1688, see `kEnvShapeTables`).

## Tables (static data, `EnvData.cpp`)

`kEnvTimeTable[64]` (0x4c2090, also used for GLIDE), `kEnvShapeTables[8*256]` (0x4c1688, shared
with mod_lfo4_22), `kVelocityCurveLinear/Exp[128]` (0x494d4c / 0x494dcc, also read by plugCore
FUN_004625d4 into slot+0xb8/+0xbc). They are initialized data in the DLL (not computed at load):
the test checks the emulator memory after load against them.

## Verification

`tests/test_env.py` (full run ~10 min, `--quick` ~3.5 min; the emulated plugin is the
bottleneck): tables; every call of the 6 entry points captured while playing all 168 programs
of banks C and D (10 notes each: velocities 1..127, keys 21..108, restruck keys), sustain-pedal
and mono/legato/glide sequences, and 60 random patches written into the edit buffer (all
envelope features: SHAPE 1..7, SMTH, MODE-T1V, CYC, L0, R, LV "X", TK, REST.ENV/REST.VC) is
replayed on the C++ object loaded from the captured bytes; outputs and bytes 4..0x7f must match.
Then direct calls of the original routines on random states (both rounding modes, other control
rates, wrap-around values, nil method pointers) and a setRate sweep over 1218 rates/modes
(exact 80-bit division).

Full run result (all bit-exact): real play ctor 64, setRate 192, start 8224 (prev: none 7180,
other voice 1044 of which 332 with REST.ENV off), release 8417 (364 with pedal held), tick
904568 (44812 with pedal held), shaped 348392; direct calls: tick 13476, start 7511, release
4490, shaped 3629, setRate 894 + 1218 sweep. All calls from plugCore run with round toward
zero, construction/setRate with round to nearest.

Coverage: every instruction of the unit is executed. Not reached by real play (only by the direct
calls): smoothing amount >= 256 (SMTH <= 63), negative TK product (TK >= 0), time index > 63,
`ticks <= 0` (table min 1 at rateScale 1), the ramp overshoot clamps at 0x45dff4/0x45e050 (dead
for consistent states: the truncated step can never pass the target), and `prev == this` in start.
