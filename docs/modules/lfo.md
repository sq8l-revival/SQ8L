# LFO — unit `mod_lfo4_22`, class `Csq_lfo` → `sq8l::Lfo`

Code range 0x45cf70–0x45dba0, VMT 0x45cf94 (no virtual methods), instance size 0xf0.
C++: `src/engine/Lfo.{h,cpp}`, tables `src/engine/data/LfoData.cpp` (generated by
`re/scripts/extract_lfo_data.py`), test `tests/test_lfo.py` + `tests/capi_lfo.cpp`.

The LFO is control-rate, almost purely integer code. Floating point appears only in the
control-rate dependent scaling (frequency → phase increment, SMTH delay rate). The port is
bit-exact on every captured call (see *Testing*).

## How plugCore drives it

* **Construction** (master ctor FUN_00461cac): 4 LFOs per voice slot, slot `i` LFO `j` at
  `master + (i*0x3a + 0x16 + j)*4` (voice slot `+0x54 + 4*j`). Created with rate
  83.592575f, then the master stores the wave callback: `+0xac = Cdoc`, `+0xa8 = LAB_0045c4f8`.
  In C++ set `lfo.waveSource = &sq8l::lfoWaveLocation` (null = unassigned: ROM waves fall back
  to TRI, as the original does when the method pointer is nil).
* **Control rate** (FUN_00462380, at load, round-to-nearest): called only when the rate
  differs from `master+0xf7c`. At load it is called twice: first with **1.0** (the sample-rate
  setup FUN_00462214 runs before the master's rate is initialized: rate 0 → clamped to 1.0),
  then with **83.592575**. Later sample-rate changes pass the same rate, so the LFOs are not
  touched again. Final state: `rateRatio = rateRatioHigh = 1.0f`, `rateRatioLow = 1/7`,
  `emuPeriod = 7296`, `defaultRate = 0`.
* **Voice start** (FUN_004625d4, inside processReplacing → **round toward zero**): writes the
  inputs `freqIn, humanIn, waveIn, level1In, level2In, delayIn, delayModeIn, reverseIn,
  oneShotIn, smoothIn` (not `amIn`, `phaseIn`, `twin*`) from the sound data, then calls
  `trigger(local_20 + max(RESET, 0), RESET >= 0)` where `local_20` is a per-start phase value
  of plugCore (`*(short*)(param_5+8)`).
* **Control tick** (FUN_00463890, every control update of an active voice, round toward
  zero): for LFO 0..3 in order, writes all inputs (below) and calls `tick()`; the result is
  stored in the voice at `+0x98 + 4*j` (modulation sources 0..3 = LFO1..4, so LFO `j+1` can be
  modulated by the fresh output of LFO `j`).
* plugCore never reads LFO fields directly (verified with a memory watch: only the input
  fields `+0xb0..+0xe4` are written, `+0xe4` is read back once); the only output is the return
  value of `tick()`. `waveKeyIn` (+0xe8) and `freqShiftIn` (+0xec) are never written (always 0).

### Inputs from the sound data (16 bytes per LFO at `sound + 0xa2 + 16*j`)

| byte | meaning | input |
|---|---|---|
| 0 | FREQ (& 0x7f) | `freqIn = FREQ << 8` (+ FM) |
| 1 | RESET (signed, <0 = OFF) | trigger argument |
| 2 | HUMAN (signed) | `humanIn` |
| 3 | WAVE (signed) | `waveIn` |
| 4 / 6 | L1 / L2 | `level1In` / `level2In` |
| 5 | DELAY (& 0x3f), bit 6 = MODE-DELAY | `delayIn`, `delayModeIn` |
| 7..8, 9 | AM source (short), amount | see below |
| 10..11, 12 | FM source (short), amount | see below |
| 13 | bits 0-1 AM mode, bits 2-3 FM mode, bit 4 REV, bit 5 one-shot | `reverseIn`, `oneShotIn` |
| 14 | PHS (& 0x3f), bit 6 twin | `phaseIn`/`twinPhaseIn`, `twinIn` |
| 15 | SMTH (& 0x3f) | `smoothIn` |

Per tick (FUN_00463890), with `fm`/`am` = source value (FUN_00463808):
* FM mode UNI/BIP: `freqIn += FMamt * fm * 2` (UNI only if `fm > 0`); PHS: `ph = FMamt*fm*4`;
  SMT: `sm = FMamt*fm`.
* AM mode UNI/BIP: `amIn += (AMamt * am) / 63` (UNI only if `am > 0`); PHS: `ph += AMamt*am*8`;
  SMT: `sm = AMamt*am*2`.
* `ph += PHS * 1024`; twin bit set → `twinPhaseIn = ph, phaseIn = 0, twinIn = 1`, else
  `phaseIn = ph, twinIn = 0` (`twinPhaseIn` keeps its old value).
* `smoothIn = sm ? (SMTH*256 + sm) / 64 (toward zero) : SMTH << 2`.

## Semantics

**Phase.** 32-bit, one cycle = 2^30 (bits 30-31 are ignored except by the one-shot end
test); wave position = bits 22..29. Phase offsets are `input << 14`, so 1024 per PHS step
→ 64 PHS steps per cycle, as for RESET (`phaseSteps << 24`).

**Frequency** (`freqToIncrement`, 8.8 fixed point, sign = direction):
`|f| < 0x700`: `inc = |f| << 14 * rateRatioLow` (linear, FREQ 0..7);
`|f| < 0x8600`: `inc = (|f| - 0x600) << 14 * rateRatioHigh`; else `2^29 * rateRatioHigh`.
Each product is rounded to Single and converted with FISTP (current rounding mode). Negated
if `(reverse > 0) != (f < 0)`. At 83.59 Hz, FREQ 7 = 0.33 Hz, 63 = 18.6 Hz, 127 = 39.5 Hz;
FREQ < 7 is linear down to 0 (FREQ 1 = 0.047 Hz). For ROM waves the increment is further
shifted right by `freqShift` (per-wave table, longer waves play slower), symmetric for negative
increments.

**Waves** (8-bit sample `b` = phase bits 22..29):
0 TRI `(b<0x80 ? b : ~b) - 0x40) * 2` (−128..126), 1 SAW `b + 0x80`, 2 SQR `b<0x80 ? 127 : 0`
(unipolar), 3 NOISE `kLfoNoise[(int8)b]` (a fixed smooth noise table, not random),
4 BIP `±127`; 5..74 oscillator waves 00..69 read from the wave ROM at
`(phase >> (30 - log2 len)) & (len-1)`, sample `s ? s - 0x80 : 0`; the wavesample is looked up
via the callback with key = table key offset (0/56/64/72/80/88) + `waveKeyIn`, **not** the
played note; 75..82 EXP..EXP4, TAN..TAN4 from `kLfoShapeTables` (shared with the envelope
SHAPE). Waves ≥ 83 → TRI (the wave is re-validated every tick since `wave` stays 0).

**Twin mode:** output = clip(wave(phase + off0) − wave(phase + off1), −127, 127).

**Smoothing** (`smoothCur > 0`): `t = 255 - s` (s clamped to 255), `A = 255 - t*t/256`,
`B = 256 - A`; `state = (state*A + v*B*256) / 256`, `v = state / 256` (divisions round toward
zero). The state is **not** reset at trigger.

**Amplitude / delay (fade).** `amp = (am << amShift) + level`, `out = amp <= 0 ? 0 :
v*amp / 256` (EMU) or `/ 2048` (SMTH) (toward zero). EMU: `levelShift 1, amShift 0`, the
level moves by DELAY per *EMU step*; SMTH: `levelShift 4, amShift 3`, the level moves by
`DELAY * rateRatio` every tick. EMU steps emulate the SQ-80's coarse LFO update: a clock
`emuClock` gets `+emuPeriod` (7296) when ≤ 0, else −1024 → one EMU step every 7.125 ticks
(11.73 Hz). When L1/L2/DELAY/mode change mid-note the fade is recomputed from the elapsed
steps (`ticks`): SMTH `L1' + ticks*DELAY`, EMU `L1' + round(ticks*DELAY*8/65)`, clamped to L2.

**Humanization** (HUMAN = 0 OFF, 1 ON, 2 1x, 3 2x, 4 4x, 5 8x, 6 16x). There is no random
number generator: on every EMU step the LFO reads `kLfoHumanize[(int8)humanIndex]` and
increments its own counter `humanIndex` (per object; no state is shared between LFOs or
voices). The table holds 23 × +1, 23 × −1, 210 × 0, arranged so that the running sum stays
in 0..2 (also over each half). A non-zero entry starts a step of ±256 (one FREQ unit) applied
over `2^(HUMAN-2)` EMU steps (1 for ON/1x), finishing any pending step first; `humanOffset` is
added to `freqIn`. So the frequency jitters between +0 and +2 FREQ units (×1, ×2 … ×16).
ON (1): not while the delay fade runs (`levelStep != 0`), and for `FREQ < 7` the plain
frequency is used; if `FREQ >= 7` but `freqIn + humanOffset < 7·256` the increment is 0.
`humanIndex` survives notes: at trigger it is masked to 0..255 and, if `humanIn < 2`, folded
to 0..127 (and the pending step dropped); `humanOffset` is cleared at trigger.

**Play modes.** REV: `reverse` negates the increment and the phase offsets. One-shot: the
LFO stops (`running = 0`, output frozen at the last value) when the phase passes 2^30;
toggling `oneShotIn` restarts it (`running = -1`).

## Quirks reproduced

* `setControlRate` compares the 80-bit 83.59257598 with the Single argument: never equal, so
  the "default" branch only triggers for NaN; `defaultRate` is 1 only between construction
  and the first `setControlRate`.
* `rateRatio = Single(K80 / rate)`: the quotient of the 80-bit constant is rounded once to 53
  bits (`divExtByFloat`, exact 128-bit integer division) then to Single.
* FISTP of out-of-range values yields 0x80000000 (`fistp32` in Lfo.cpp; `Fpu.h::fistp` would
  wrap instead). Only reachable with tiny control rates.
* Changing HUMAN takes effect on the frequency one tick late (`updateParams` uses the
  previous mode, then copies the new one).
* `phaseOffset[1]` keeps flipping sign every tick in reverse / negative-frequency playback
  when twin is off (harmless: unused).
* `freqSeen` (+0x34) is written but never read; `trigger` sets it to 0x80000000.
* The "unassigned callback" test looks at the high word of the code pointer only (Delphi
  `Assigned` on a method pointer).
* Smoother state persists across notes; `trigger` only clears `smoothCur`, so the weights are
  recomputed on the next tick.

## Rounding mode

`tick()` and `trigger()` run inside processReplacing → call them under
`RoundTowardZero` (all captured calls had FPCW 0x0E7F). `construct()` / `setControlRate()`
run at load → `RoundToNearest`. With the standard rate (ratio exactly 1.0, 1/7) the mode
still matters for FREQ < 7 (`rateRatioLow` is not exact) and for SMTH delay steps only when
`rateRatio != 1`.

## Tempo sync (port addition)

Issue #42. The SYNC field of an LFO page (`ofs::Lfo::SyncBit`, see
[program.md](program.md#sync-port-addition)) makes FREQ a note value at the host's tempo.
Not in the original, so it is not in its object either: `syncInc`, `syncLock` and `syncPhase`
sit after the 0xf0 bytes the differential tests map, and the master writes them before every
`tick()` through `VoiceModules::lfoSetSync` (increment 0 = FREE).

* **Division.** In `Master::controlUpdate`, after the LFO's inputs: `d = clamp((freqIn +
  0x80) >> 8, 0, 35)`, i.e. FREQ plus its UNI/BIP frequency modulation, rounded. Modulation
  steps through the divisions, so the LFO always plays one of them; HUMAN does not apply.
* **Rate.** `syncInc = 2^30 * q / kSyncQuarters[d]`, `q` the quarter notes per LFO tick:
  `bpm / 60 * (controlStep + 1024) / (512 * sampleRate)` (two control updates per tick).
  Truncated, at least 1, and capped at 2^29, half a cycle per tick, the free LFO's top.
* **In the LFO.** `updateParams` computes the original's increment, then replaces it with
  `±syncInc` (negative for REV), so the original's code runs unchanged. `freqShift` is not
  applied: one cycle is one division for the ROM waves too. The phase offsets (PHS, twin)
  follow the sign as they do for a free LFO; a one-shot stops at the end of its cycle.
* **Phase.** RESET=n restarts the phase per note as before. RESET=OFF locks it to the song:
  every tick the phase is set to `frac(position / cycle) * 2^30` (negated for REV), so every
  voice lines up with the bar grid. The position is the host's while its transport plays
  (`Master::setTransport`, once per block, then advanced per sample); stopped, or with a host
  that has none, it runs on at the host's tempo from where it was, so the locked LFOs stay in
  step with each other. An implausible tempo (outside 1..999) is taken as 120.
* **Song position.** DPF hands over bar, beat and tick, which each format wrapper derives
  from the host's position its own way; `SQ8LPlugin::songQuarters` undoes the one the binary
  was built with (they differ only for a meter whose denominator is not 4).

`sq8l_render_check --tempo-sync` checks the rate per division and tempo, FREQ past the last
division, the cap, FM in both directions, and the lock (host position, stopped transport,
REV). With SYNC off nothing changes: the regression renders stay identical to the original.
